# Phase 7 — Sprint 15: CMS Admin Panel

- **Phase:** 7 — CMS Admin Panel
- **Sprint:** 15
- **Priority:** 🟢 Medium
- **Django App(s):** `cms`
- **Depends on:** all prior phases

---

## Goal

Give non-technical staff a single admin surface to manage the system: dashboard, visual template editor, keyword manager, company/user management, report scheduling, and system settings.

---

## Tasks

- [ ] Custom admin dashboard (base on `django-jazzmin`/`grappelli`, or a dedicated SPA admin)
- [ ] Dashboard widgets:
  - Patient count (today, this week, total)
  - Examinations today
  - Pending imports
  - Sync conflicts
  - Recent activity log
- [ ] **Department Manager:**
  - CRUD for `Department` (Lâm sàng, Xét nghiệm máu, X-Quang, Siêu âm, ...)
  - Each department has its own field table
- [ ] **Department Template Editor:**
  - Tabular form builder per department: add/remove columns (fields)
  - Field types: text, number, select, multi-select, boolean, date, textarea
  - Per-field settings: key, label, type, unit, required, order, normal_range, default_price, test_category
  - Import columns from Excel (auto-generate template from column headers)
  - Version history
- [ ] **Exam Package Manager:**
  - CRUD for `ExamPackage`: name, exam_type, description
  - Department picker: select departments + their template version
  - Set default_package_price
  - Drag-to-reorder departments
- [ ] **Company Package Assignment:**
  - Assign ExamPackage to company with pricing mode
  - Per-field pricing grid (pre-filled with default_price)
  - Flat package price option
- [ ] Keyword Manager:
  - CRUD for DiseaseCode + DiagnosisKeyword
  - Bulk import from `Benh-TuVan 001.xlsx`
  - Test diagnosis: input findings text → see suggested matches
  - Re-embed keywords button
- [ ] Company Management:
  - CRUD for companies
  - Employee list per company
  - Import employee list from Excel
  - Company admin accounts
- [ ] User Management:
  - User CRUD + invite
  - Role assignment
  - Activity log per user
  - Login history
- [ ] Report Management:
  - Schedule recurring reports
  - Generated report history
  - Report template editor
- [ ] System Settings:
  - Clinic name, address, phone, email, logo
  - Print header/footer text
  - Default exam types
  - QR code settings (size, format)
  - Email configuration (for result notifications)

---

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/admin/dashboard/` | Dashboard stats |
| GET/POST | `/api/admin/disease-codes/` | Disease code CRUD |
| GET/POST | `/api/admin/companies/` | Company management |
| GET/POST | `/api/admin/users/` | User management |

---

## Acceptance Criteria

- Admin can build/edit an exam template visually and save valid `fields_config`
- Keyword manager supports bulk import + live diagnosis test + re-embed
- Company/user management works with role assignment and invite flow
- Dashboard widgets show live counts
- System settings persist and are reflected in prints/reports (logo, header/footer)
- All CMS actions restricted to Admin (per matrix)

---

## Technical Notes

- The template editor produces the same `fields_config` JSON Schema consumed by Sprint 4 — validate on save.
- "Test diagnosis" reuses the Sprint 8 `suggest/` endpoint.
- Keep the CMS thin: it orchestrates existing app APIs rather than duplicating logic.
