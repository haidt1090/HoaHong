# Phase 5 — Sprint 11: PWA Setup

- **Phase:** 5 — Offline PWA
- **Sprint:** 11
- **Priority:** 🟡 High
- **Django App(s):** frontend (Service Worker, manifest)
- **Depends on:** a working SPA (Phases 1-4 frontend)

---

## Goal

Turn the SPA into an installable Progressive Web App with a Service Worker caching strategy, offline fallback, and an online/offline indicator. This is the foundation for offline data sync (Sprint 12).

---

## Tasks

- [ ] Service Worker via Workbox webpack plugin
- [ ] Caching strategies:
  - Static assets (JS, CSS, fonts): **Cache-First**
  - API GET requests: **Network-First** with cache fallback
  - API POST/PUT/DELETE: **Network-Only** (queued if offline — Sprint 12)
  - Images: **Cache-First**
- [ ] `manifest.json`:
  - `name`, `short_name`, `description`, icons (192px, 512px)
  - `start_url`: `/khamsk/`
  - `display`: `standalone`
  - `background_color`, `theme_color`
- [ ] Install prompt handling (`beforeinstallprompt` event)
- [ ] Offline fallback page (cached on first load)
- [ ] Online/offline indicator UI (green dot / red dot)
- [ ] Register service worker + update flow

---

## Caching Strategy Summary

| Resource | Strategy | Rationale |
|----------|----------|-----------|
| JS/CSS/fonts | Cache-First | Rarely change; instant load offline |
| API GET | Network-First → cache | Fresh when online, usable offline |
| API mutations | Network-Only (queue) | Must reach server; queued in Sprint 12 |
| Images | Cache-First | Static assets |

---

## Acceptance Criteria

- App is installable (Add to Home Screen / desktop install prompt)
- After first visit, static assets load with no network
- API GET responses are served from cache when offline
- An offline fallback page shows for uncached navigations
- Online/offline indicator reflects real connectivity
- Service Worker update flow prompts/refreshes on new deploy

---

## Technical Notes

- `start_url` and SW scope must be `/khamsk/` (the app runs under a subpath).
- Precache the app shell + offline fallback during SW install.
- Version the SW cache; clean old caches on `activate`.
- Do **not** cache API mutations here — queuing is handled in Sprint 12.
