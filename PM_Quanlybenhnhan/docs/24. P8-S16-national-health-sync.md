## Goal

Đồng bộ dữ liệu khám sức khỏe (kết quả khám) từ hệ thống lên **Cổng dữ liệu sức khỏe Quốc gia** (CSDLKSK — https://admin.csdlksk.vn) thông qua API của Trục dữ liệu Bộ Y tế (EMRHUB). Tính năng chỉ dành cho Admin.

---

## Context

Hệ thống cần đẩy dữ liệu KSK lên CSDLKSK theo chuẩn API của Bộ Y tế:
1. **Đăng nhập** lấy bearer token (`POST /api/auth/login`)
2. **Đồng bộ dữ liệu** (`POST /api/platform/data-sync/push`) với body gồm header + data (XML base64) + chữ ký số RSA-SHA256

## Data Flow

```
1. Admin chọn phạm vi: Công ty (chọn công ty + thời gian) HOẶC Bệnh nhân lẻ
2. Admin click "Kiểm tra" → POST /api/sync/validate/
   → Kiểm tra tất cả examination trong phạm vi đã complete/confirmed chưa
   → Nếu chưa: cảnh báo + liệt kê examination chưa complete + KHÔNG cho sync
   → Nếu đủ: enable nút "Đồng bộ"

3. Admin click "Đồng bộ" → tạo SyncJob → Celery task

4. Celery task:
   a. Login → bearer token
   b. Lấy các Examination cần sync (theo scope_type + filters)
   c. Build XML KHAMSUCKHOE (base64)
   d. Build header (msg_id, send_datetime...)
   e. Sign RSA-SHA256(headerSha.dataSha)
   f. POST /api/platform/data-sync/push
   g. Lưu response → SyncJob.status = done/failed

5. Admin xem kết quả tại https://admin.csdlksk.vn
```

## Technical Notes

- **Chữ ký số API (RSA-SHA256 — bắt buộc khi push)**: `headerSha = SHA256(json.dumps(header)).upper()`, `dataSha = SHA256(data).upper()`, `signature = base64(RSA_SHA256(headerSha + "." + dataSha))`.
  - **Quan trọng**: `header` được stringify với đúng thứ tự field như khi gửi; `data` là chuỗi **base64 XML** đã trim trước khi SHA256.
  - Đây là chữ ký gói tin `{header, data}` gửi lên EMRHUB (`POST /api/platform/data-sync/push`), dùng `SyncConfig.private_key`. **Không** liên quan khối `CHUKYDONVI` trong XML.

- **`CHUKYDONVI` trong XML hồ sơ** (khác chữ ký API):
  ```xml
  <CHUKYDONVI>
    <CKS_NGUOI_KET_LUAN></CKS_NGUOI_KET_LUAN>
    <CKS_BENH_VIEN></CKS_BENH_VIEN>
  </CHUKYDONVI>
  ```
  - `CKS_NGUOI_KET_LUAN`: chữ ký **số** của người kết luận (bác sĩ).
  - `CKS_BENH_VIEN`: chữ ký **số** của cơ sở KCB / bệnh viện.
  - **CSDLKSK kỳ vọng chữ ký số (chứng thư / USB token)**, tức Base64 của gói ký mật mã
    (thường CMS/PKCS#7 hoặc XML Signature — không phải Base64 của **ảnh PNG** chữ ký tay).
    Hướng dẫn nhập phiếu trên cổng cũng gọi đây là *“Chữ ký số của người kết luận và
    của cơ sở khám”*; không có thì phiếu không hoàn tất. VN Core FHIR map
    `CKS_NGUOI_KET_LUAN` → Provenance.signature với `sigFormat = application/signature+xml`.
  - **Gap hiện tại của app**: trang **Sync → Chữ ký số** chỉ lưu **ảnh PNG / chuỗi base64 ảnh**
    rồi nhét vào `CKS_*`. Chuỗi đó là Base64 hợp lệ về mặt encoding, nhưng **không phải
    chữ ký số** → CSDLKSK vẫn có thể báo
    *"CKS_NGUOI_KET_LUAN hoặc CKS_BENH_VIEN bị thiếu (null/empty) hoặc không phải Base64 hợp lệ"*
    (data đã lên kho, chữ ký hồ sơ bị từ chối).
  - Sample `KHAMSUCKHOE_sample.xml` để hai thẻ **rỗng** — không phải ví dụ ảnh PNG.
  - **Chưa làm**: tích hợp USB token / chứng thư số để ký nội dung hồ sơ rồi ghi Base64
    chữ ký số vào `CKS_*`. Cần làm sprint riêng (ký theo bác sĩ + tổ chức, HSM/token).
  - Một file XML chỉ có một khối `CHUKYDONVI` → sync nhóm theo bác sĩ kết luận.
  - **Workaround tạm**: sau khi push API, ký USB Token trên cổng
    [admin.csdlksk.vn](https://admin.csdlksk.vn) (Token Service + Viettel-CA) —
    [hướng dẫn Viettel](https://viettelhue.vn/huong-dan-ky-so-bang-usb-token-viettel-ca-tren-cong-du-lieu-suc-khoe/).
  - **MySign API (ghi chú — chưa tích hợp)**: ký số từ xa Viettel-CA; bác sĩ xác nhận
    trên app Mysign (không cần USB trên máy web). Tài liệu:
    [API sync/async](https://viettel-ca.vn/tin-tuc/huong-dan-tich-hop-api-dich-vu-mysign-cho-cac-he-thong-ung-dung-cntt),
    [PDF v1.8](http://viettel-ca.vn/download/soft/tai_lieu_tich_hop_dich_vu_mysign_api+sdk_v1.8.pdf).
    Base: `https://remotesigning.viettel.vn/vtss/service/`.
    Luồng đồng bộ: `Login` → `CertificateInfo` (`credential_id`) → `SignHash`
    (`hash` = SHA-256 Base64, `async=0` chờ xác nhận / `1` poll / `3` callback).
    Cần hợp đồng Viettel (`client_id` / `client_secret` / `profile_id` / `user_id`).
    Map vào app: hash XML (hoặc phần ký) → `signatures[0]` → `CKS_*` trước khi push.
    **Cần xác nhận với Viettel/BYT**: raw RSA signature của hash có đủ cho `CKS_*`
    hay phải bọc CMS/PKCS#7 / XML Signature kèm certificate chain.

- **EMRHUB `ERROR_99` / `res_msg: Unknown error`**: mã lỗi chung phía Trục (HTTP 400),
  thường không giải thích chi tiết. Nguyên nhân hay gặp khi liên thông:
  1. XML lệch schema so với sample (thiếu khối khung / `CHUKYDONVI`, thiếu `NOIDUNGFILE`…).
  2. Chữ ký RSA không khớp (private key sai, hoặc `data`/`header` đổi sau khi ký).
  3. Thiếu trường nghiệp vụ bắt buộc trên hồ sơ (CCCD, mã CSKCB, …).
  Cách xử lý: so XML vừa push với `documents/KHAMSUCKHOE_sample.xml`; kiểm tra
  `SyncConfig.private_key` / sandbox credentials; xem log `SyncJob.error_message`.

- **Không dùng giá trị mẫu từ `KHAMSUCKHOE_sample.xml`**: XML1/XML2 chỉ ghi
  dữ liệu thật (bệnh nhân, exam, SyncConfig). Các filler kiểu `TUAN_THAI=0`,
  `MA_NGHE_NGHIEP=04`, `NGUON_CHI_TRA=2`, `MA_LOAI_KCB=01`,
  XML9 mặc định `"0"` đã bỏ — thẻ trống bị strip. `MA_DAN_TOC` là trường bắt buộc
  với Adult: mặc định `01` (Kinh) khi bệnh nhân chưa có mã; dùng `ethnicity_code`
  / `ma_dan_toc` nếu có. `MA_NGHE_NGHIEP` chỉ có khi
  patient có `occupation_code` / `ma_nghe_nghiep`. `LY_DO_VV` / `DOI_TUONG`
  lấy theo `exam_type` (không fallback sang sample).
- **Mọi trạng thái phiếu đều sync được** (draft / completed / confirmed).
- **Đồng bộ tất cả**: bỏ qua lượt đã `SyncJob` thành công cùng môi trường
  (`synced_examination_ids` hoặc `examination_id`). Đồng bộ từng phiếu vẫn
  cho phép đẩy lại. Job ghi `success_count` / `failed_count` / `skipped_count`.
- **XML rỗng**: `strip_empty_elements` chỉ bỏ thẻ dữ liệu optional trống; giữ
  `PRESERVE_EMPTY_TAGS` (khung hồ sơ + `CHUKYDONVI`). Chữ ký RSA API ký trên
  XML đã làm sạch.
- **Thư viện**: `cryptography` (RSA signing), `requests` (HTTP), `xml.etree.ElementTree` hoặc `lxml` (XML).
- **msg_id**: `sender_id + YY + MM + DD + UUID4 (bỏ dấu gạch ngang)`.
- **send_datetime**: `int(time.time() * 1000)` (13 chữ số).
- **data_type**: `xml/base64` — XML được encode base64.
- **service-type header**: `100` (Đồng bộ dữ liệu từ HIS/EMR lên Trục).
- **Bảo mật**: private key KHÔNG được log, KHÔNG commit vào repo, lưu qua env hoặc DB encrypt.
- **Sandbox trước**: phải test thành công trên Sandbox rồi mới triển khai Production.
