# Phase 2 — Frontend Sprint: Examination UI

- **Phase:** 2 — Examination Core
- **Sprint:** F1 (companion to Phase 2 backend sprints)
- **Priority:** 🔴 Critical
- **Depends on:** Phase 1 Frontend (P1-SF1), Sprint 4-6a backend APIs
- **Runs in parallel with:** Sprint 5-6a

---

## Goal

Build the examination management pages using the new department-driven model: a **multi-tab form** (one tab per department), department-level role locking, status workflow UI, Excel import page, company package assignment page, and a **data entry mode** on Company Detail for per-employee exam result entry with multi-package support.

---

## Tasks

### Multi-Tab Department Form (`DynamicExamForm`)
- [ ] Fetches exam data via `GET /api/examinations/{id}/form/` → returns `department_results[]` with `template_snapshot[]`
- [ ] Renders a tab bar: one tab per department (ordered by `ExamPackageDepartment.order`)
- [ ] Tab label = department name
- [ ] Tab content = dynamic table of fields from that department's `template_snapshot`:
  - Columns: field label, input, unit, normal range indicator
  - Supported field types (same as before): `text`, `number`, `select`, `multi-select`, `boolean`, `date`
  - Normal range highlighting: green/red border based on `normal_range`
- [ ] Tab shows completion status: green checkmark if department has all required fields filled
- [ ] Nurse sees all department tabs but only `category='clinical'` tabs are editable (others greyed out with lock icon)
- [ ] LabTech sees all tabs but only `category='para_clinical'` tabs are editable

### Examination Create Flow
- [ ] Step 1: Select patient (search dropdown + QR scan stub)
- [ ] Step 2: Select company exam package (filtered by patient's company)
- [ ] Step 3: DynamicExamForm with empty department tabs
- [ ] "Save Draft" → saves all department data
- [ ] Each department has its own "Save" button in its tab (so Nurse can submit Lâm sàng, LabTech XML later)

### Examination List Page
- [ ] Filterable table: patient name, employee_code, company, exam_type, exam_date, doctor, status
- [ ] Status badges: draft (grey), completed (blue), confirmed (green)
- [ ] Department completion indicator: e.g., `3/5 departments done` shown as a progress bar in the row

### Examination Detail/View Page
- [ ] Read mode: all departments shown as tabs, each department's data in a table
- [ ] Edit mode (for user's assigned departments only): editable fields in their tabs
- [ ] Conclusion section: textarea + "Suggest Diagnosis" button (Phase 3 API, stubbed)
- [ ] Disease selector dropdown
- [ ] Status actions: Complete (doctor), Confirm (doctor/admin), Delete (draft only)

### Company Package Assignment Page
- [ ] Page: `/companies/{id}/packages/`
- [ ] Product card grid: each assigned package shown as a card
- [ ] "Assign Package" button → modal:
  - Select exam package
  - Choose pricing mode:
    - Per-field: table of all department fields with price inputs (pre-filled with `default_price`)
    - Package total: single price input
- [ ] Edit/Deactivate existing package assignments

### Excel Import Page (Per-Department)
- [ ] Import page route: `/examinations/import/`
- [ ] Step 1: Select company (dropdown of companies)
- [ ] Step 2: Select exam package — filtered to active packages for selected company (via `/api/companies/{id}/packages/`)
- [ ] Step 3: Select department — filtered to departments in the selected company's exam package
  - **"Xuất Excel" button** → triggers async export:
    - `POST /api/export/` → returns `{export_id, status: 'processing'}` instantly
    - Button changes to disabled state with progress spinner + text: `"Đang tạo file... 45/200"`
    - Polls `GET /api/export/{id}/` every 1-2 sec for progress updates
    - When `status === 'done'`: button changes to "Tải xuống" with download icon, auto-triggers `GET /api/export/{id}/download/`
    - On failure: red error toast + "Thử lại" button
  - File contains all company employees (employee_code, full_name) + existing exam data pre-filled
- [ ] Step 4: Select exam date (default: today)
- [ ] Step 5: Upload Excel file (drag-and-drop or file input)
- [ ] Step 6: Column mapping preview:
  - System auto-matches columns by **Vietnamese label** (header row = `field.label`, not `field.key`)
  - User can adjust mismatched columns via dropdown per column
  - Matched fields shown in green, unmatched in yellow
- [ ] Step 7: Import → POST `/api/examinations/import/{department_id}/`
  - Progress bar (poll `/api/import/{id}/status/`)
  - Completion: `success_count`, `updated_count`, `skipped_count`, `errors[]` table
- [ ] Each department imports independently; importing XN máu does not touch Lâm sàng

### Employee Import (Company Detail → Employee Tab)
- [ ] Company detail page → Tab "Nhân viên": 
  - "Tải mẫu Excel" button → downloads employee list template (columns: employee_code, full_name, dob, gender, department, phone, email)
  - "Nhập Excel" button → opens EmployeeImportModal
- [ ] EmployeeImportModal:
  - Step 1: File upload (drag-drop or file input)
  - Step 2: Column mapping preview (auto-match columns by header)
  - Step 3: Import → `POST /api/patients/import/` with `{company_id, file}`
  - Result: `{created, skipped, errors[]}` summary
- [ ] Backend: `POST /api/patients/import/` — bulk import patients into a company

### Data Entry Tab (Company Detail → Tab "Nhập liệu")
- [ ] Route: `companies/:id` with tab "Nhập liệu"
- [ ] **Layout: 3-panel split** — Top row: search + package selection; Bottom: data entry area
- [ ] **Panel A — Employee Search** (top-left):
  - Search bar with debounce 300ms: tìm theo `employee_code` hoặc `full_name`
  - API: `GET /api/patients/?search=<q>&company=<id>`
  - Results dropdown/list below search bar: shows `employee_code - full_name`
  - Click a result → loads that employee's existing exams & data into Panel C
  - Selected employee highlighted with a chip/tag above Panel C
- [ ] **Panel B — Package Selection** (top-right):
  - Fetch active company packages: `GET /api/companies/{id}/packages/`
  - Display as selectable chips/cards: each package name + exam_type label
  - Click to toggle selection (multi-select allowed — một nhân viên có thể khám nhiều gói)
  - Selected packages highlighted (filled color), unselected (outlined)
  - On selection change → Panel C refreshes with the combined fields of all selected packages
- [ ] **Panel C — Data Entry Area** (bottom, full-width):
  - Header bar: `Đã chọn: [employee_name] | Gói: [package_1] [package_2]`  
  - For each selected package, render a **package block**:
    - Package title: `[ExamPackage.name]` + badge trạng thái (Chưa nhập / Đang nhập / Đã hoàn thành)
    - Inside: one sub-section per department (ordered by `ExamPackageDepartment.order`)
    - Each department sub-section: collapsible accordion with header `[Department.name]` + completion indicator
    - Body: `FieldTable` — **horizontal column layout** (mỗi chỉ số = 1 cột):

```
┌──────────┬──────────────────────┬──────────────┬─────────────────────────┬─────┐
│          │ Huyết sắc tố (g/dL)  │ ALT (U/L)    │ Huyết áp tâm thu (mmHg) │ ... │
├──────────┼──────────────────────┼──────────────┼─────────────────────────┼─────┤
│ Kết quả  │ [___input___]        │ [___input__] │ [___input___]           │ ... │
├──────────┼──────────────────────┼──────────────┼─────────────────────────┼─────┤
│ BT       │ 12-16                │ <40          │ 90-140                  │ ... │
└──────────┴──────────────────────┴──────────────┴─────────────────────────┴─────┘
```

      - **Row 1** — Column headers: `[label] ([unit])` — e.g., `Huyết sắc tố (g/dL)`
      - **Row 2** — Input cells: one input per column, type matching the field definition (`number`, `text`, `select`, `date`, etc.)
      - **Row 3** — Normal range reference: `min-max` displayed in muted text; highlights green (in range) / red (out of range) as user types
      - Fields without unit show only the label in header row
      - Horizontal scroll if too many columns — department name stays fixed (sticky column)
  - Data flow:
    - On employee + package selection → `GET /api/examinations/?patient=<id>&company=<id>` to find existing exams
    - If exam exists for that package → load `DepartmentResult.data` via `GET /api/examinations/{id}/form/`
    - If no exam exists → display empty fields (template loaded from package's department templates)
  - Field data stored locally in a reactive `Map<packageId, Map<deptId, Record<fieldKey, value>>>`
- [ ] **Save button** at bottom of Panel C:
  - On click → for each selected package:
    - Ensure `Examination` exists (create if new via `POST /api/examinations/`)
    - For each department with dirty data: `PUT /api/examinations/{exam_id}/departments/{dept_id}/`
    - Then `PATCH /api/examinations/{exam_id}/departments/{dept_id}/complete/` for fully-filled departments
  - Show toast: "Đã lưu kết quả cho [employee_name] — [n] gói"
  - Auto-select next employee in search results for fast bulk entry (optional skip button)
- [ ] **UX optimizations:**
  - Keyboard shortcut: Enter on search → auto-select first result; Tab → jump to next field
  - Normal range highlight on-the-fly: green/red border as user types in number fields
  - Dirty indicator: asterisk `*` next to department name when unsaved changes exist
  - Collapse all departments by default except the first one; expand on click
  - "Xoá dữ liệu đã nhập" button per department to reset fields to empty
- [ ] **Backend requirements:**
  - `GET /api/patients/?search=<q>&company=<id>` — search employees within company (exists)
  - `GET /api/companies/{id}/packages/` — active company packages (exists)
  - `GET /api/examinations/?patient=<id>&company_exam_package=<id>` — find existing exam (exists)
  - `POST /api/examinations/` — create exam if none exists (exists)
  - `GET /api/examinations/{id}/form/` — get department templates + existing data (exists)
  - `PUT /api/examinations/{exam_id}/departments/{dept_id}/` — save department data (exists)

## Technical Notes

- Once the exam is loaded, the `form/` endpoint returns all department snapshots in one call — no need to call per-department.
- Department tabs use lazy rendering: only the active tab's fields are in the DOM.
- Package pricing modal: fetch all department templates from the package → flatten all fields into a single pricing table.
- **Data entry panel**: employee + package → fetch existing exams, apply department data into field tables. Save iterates per package/exam, creating exams on-demand if needed.
- Employee search is debounced (300ms) and scoped to the current company via `company=<id>` query param.
- Field dirty state tracked locally via a `Set<fieldKey>` — cleared on successful save.
