# Phase 1 — Sprint 2: Auth & User System

- **Phase:** 1 — Foundation
- **Sprint:** 2
- **Priority:** 🔴 Critical
- **Django App(s):** `accounts`
- **Depends on:** Sprint 1 (project scaffold)

---

## Goal

Implement authentication (JWT) and the custom user model with role support. Provide login, logout, token refresh, profile management, and an admin-driven user invite flow.

---

## Tasks

- [ ] Custom User model (`AbstractUser`)
  - Fields: `email` (login identifier), `phone`, `full_name`, `role`, `is_active`, `is_staff`
  - `role` choices: `admin`, `doctor`, `nurse`, `labtech`, `company_admin`
- [ ] Group-based permissions per role (Django Groups seeded via data migration)
- [ ] JWT authentication via `djangorestframework-simplejwt`
  - Access token (15 min) + Refresh token (7 days)
  - Token blacklist on logout
- [ ] Endpoints:
  - `POST /api/auth/login/`
  - `POST /api/auth/logout/`
  - `POST /api/auth/refresh/`
  - `GET  /api/auth/me/`
  - `PUT  /api/auth/me/` (update profile)
  - `POST /api/auth/change-password/`
- [ ] Admin user invite flow:
  - Admin creates user → system sends credentials → first login forces password change
- [ ] Rate limiting on login attempts (e.g. `django-axes` or DRF throttling)

## Data Model

```python
class User(AbstractUser):
    ROLE_CHOICES = [
        ('admin', 'Quản trị viên'),
        ('doctor', 'Bác sĩ'),
        ('nurse', 'Điều dưỡng'),
        ('labtech', 'Kỹ thuật viên'),
        ('company_admin', 'Quản trị công ty'),
    ]
    email = models.EmailField(unique=True)
    phone = models.CharField(max_length=20, blank=True)
    full_name = models.CharField(max_length=255)
    role = models.CharField(max_length=20, choices=ROLE_CHOICES)
    must_change_password = models.BooleanField(default=False)
    company = models.ForeignKey('accounts.Company', null=True, blank=True, on_delete=models.SET_NULL)

    USERNAME_FIELD = 'email'
    REQUIRED_FIELDS = ['full_name']
```

> Note: `company` FK links a `company_admin` user to their company. `Company` model itself is fleshed out in Sprint 3, but a stub is created here.

---

## Acceptance Criteria

- User can log in with email + password and receive access + refresh tokens
- Expired access token can be refreshed with a valid refresh token
- Logout blacklists the refresh token (cannot be reused)
- `GET /api/auth/me/` returns current user with role
- New users created by admin are forced to change password on first login
- After N failed login attempts, further attempts are throttled

---

## Technical Notes

- Set `AUTH_USER_MODEL = 'accounts.User'` **before** the first migration.
- Seed role Groups with a data migration so permissions are reproducible.
- Return `role` and `must_change_password` in the login response so the frontend can route appropriately.
