# Phase 3 — Sprint 8: Vector Search Engine

- **Phase:** 3 — Diagnosis Engine
- **Sprint:** 8
- **Priority:** 🟡 High
- **Django App(s):** `diagnosis`
- **Depends on:** Sprint 7 (keywords/diseases), Phase 2 (examinations with DepartmentResult), PostgreSQL + pgvector

---

## Goal

Enable semantic diagnosis suggestion and similar-case retrieval using pgvector, across the dynamic department-driven examination model.

---

## Tasks

- [ ] Django migration: `CreateExtension("vector")`
- [ ] VectorField on: `DiagnosisKeyword.embedding`, `DiseaseCode.embedding`, `Examination.embedding`, `Patient.embedding`
- [ ] Embedding generation:
  - Model: `paraphrase-multilingual-MiniLM-L12-v2` (384d, multilingual)
  - For **Examination**: embed the aggregated findings text from all `DepartmentResult.data` values (using `aggregate_findings()` from Sprint 7)
  - For **Patient**: embed name + demographics
  - Celery task triggered on create/update
- [ ] Diagnosis suggestion API:
  - `POST /api/diagnosis/suggest/`
  - Input: `{ "examination_id": N }`
  - Backend aggregates findings from DepartmentResults → embeds → pgvector search → returns top 5
  - Or input: `{ "findings_text": "..." }` for direct text search
  - Fallback: keyword substring matching if vectors unavailable
- [ ] Similar case search API:
  - `POST /api/diagnosis/similar-cases/`
  - Uses `Examination.embedding` (which encodes all department results)
- [ ] Re-embed command: `python manage.py reembed --all`

---

## Indexing Strategy

```sql
CREATE INDEX CONCURRENTLY idx_keyword_embedding
  ON diagnosis_keyword USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 200);

CREATE INDEX CONCURRENTLY idx_examination_embedding
  ON examination USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);
```

## Acceptance Criteria

- pgvector extension enabled via migration
- Examination embedding generated from all department result values
- Diagnosis suggestion returns relevant diseases ranked by confidence
- Similar cases retrieval works across department-diverse exams
- Embedding model runs locally (no external API → works offline)

---

## Technical Notes

- The key difference from the old design: `Examination.embedding` is now built from `DepartmentResult.data` values, not from 5 hard-coded JSONFields. The aggregation function from Sprint 7 builds the text.
- Re-embedding after language model changes must iterate all examinations and re-aggregate DepartmentResults.
- Re-embed task is async (Celery) to handle large datasets.
