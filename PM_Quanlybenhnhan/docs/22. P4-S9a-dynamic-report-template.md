---

## Goal

Replace the hardcoded Excel export with a **dynamic template engine**. Admin creates `ReportTemplate` (composite: header + body + footer) and `DepartmentReportTemplate` (per-department body). Templates use Django template syntax with predefined shortcodes. Body can be a coded function (e.g., `clinical_detail_table`) OR a list of department sub-templates. Output: HTML (PDF đã được loại bỏ).

---

## Architecture

```
ReportTemplate (composite)
├── header_xlsx          ← uploaded .xlsx letterhead (static; Excel merge)
├── footer_xlsx          ← uploaded .xlsx letterhead (static; Excel merge)
├── body_type            ← "department_templates" | "clinical_detail_table" | "summary_stats"
├── body_config          ← JSON params cho body function
├── logo                 ← ImageField
└── items ──→ ReportTemplateItem[]
                └── DepartmentReportTemplate
                      ├── department: FK (null = global)
                      ├── body_html: Django tpl
                      └── config: JSON
```

### Render Flow

```
1. Build context: clinic, company, exam_package, patients[], department_results[]
2. Render body:
   - IF body_type = coded function → BodyBuilder.render(body_type, data, config)
   - IF body_type = "department_templates" → for each item:
       render item.department_template.body_html with dept-level context
3. HTML export: body only (no HTML letterhead)
4. Excel export: build body workbook, merge header_xlsx / footer_xlsx (static)
5. Save .html or .xlsx
```

### Report Generation (updated)
| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/reports/generate/` | Generate report (thêm `template_id`) |

```json
{
  "company_id": "uuid",
  "exam_package_id": "uuid",
  "exam_date": "2026-05-26",
  "report_type": "clinical_detail",
  "output_format": "html",
  "template_id": "uuid"
```

- `template_id` bỏ trống → tự dùng template `is_default` của `report_type` đó.

- `output_format: "html"` bắt buộc phải có template.

## Technical Notes

- **Backward compatible**: Report.template nullable → fallback Excel cũ nếu không chọn template.
- **Department auto-match**: `ReportTemplateItem.department` null → render DepartmentReportTemplate cho khoa khớp với `DepartmentReportTemplate.department` của template đó.
- **Coded body functions**: `BodyBuilder` là class dispatch. Mỗi function nhận `(dataset, config, context)` → return HTML string.
- **HTML-only output**: CSS `@page { size: A4 landscape; }` cho report ngang khi in từ trình duyệt. Font Unicode hỗ trợ tiếng Việt.

## Implementation Notes (khác với spec ban đầu)

1. **Route prefix**: dùng `/api/report-templates/` làm canonical thay vì
   `/api/templates/report/` (xung đột với `DepartmentTemplateViewSet`). Alias vẫn
   được giữ — xem bảng Endpoints.

2. **Editor thay cho CodeMirror 6**: CodeMirror 6 là ESM, cần bundler hoặc CDN.
   Dự án không có build step cho asset của Django admin và có thể deploy ở môi
   trường không có internet ra ngoài. Thay vào đó `reports/static/reports/template_editor.js`
   cài sẵn một editor không phụ thuộc: highlight HTML + Django tag, số dòng,
   variable picker, nút preview. Nếu sau này thêm bundler, có thể thay bằng
   CodeMirror 6 mà không đổi API của widget.

3. **`ReportTemplateItem.exam_template`** (thêm mới): một khoa có thể được gán
   nhiều mẫu nhập liệu trong cùng gói khám (Sprint 4a — ví dụ khoa "Xét nghiệm"
   có cả "XN máu" và "XN nước tiểu"). Chỉ khớp theo `department` sẽ render nhầm
   cả hai vào một block, nên item có thêm FK tuỳ chọn để ghim đúng mẫu.

4. **`ReportDataset` (report_builder.py)**: `ReportData` cũ dùng namespace
   `{field_key: value}` phẳng nên hai khoa trùng `key` sẽ đè nhau (`key` chỉ
   unique trong một template). Engine mới dùng cấu trúc lồng
   `patient.departments[].fields[]` kèm cờ `is_abnormal`. `ReportData` cũ vẫn
   được build và gắn vào `dataset.table` để các body function dạng bảng tái sử
   dụng logic gộp cột/merge header.

5. **Template sandbox**: `header_html` / `body_html` / `footer_html` được compile
   bằng một `django.template.Engine` riêng đã gỡ các tag `include`, `extends`,
   `ssi`, `load`, `debug` (đọc file trên đĩa / nạp thư viện tuỳ ý). Quyền sửa
   template giới hạn ở role Admin (`ReportTemplatePermission`).

6. **`pydyf` pin**: WeasyPrint 62.x chỉ tương thích API pydyf 0.10; pydyf ≥0.11
   làm PDF lỗi `AttributeError: 'super' object has no attribute 'transform'`.
   Đã pin `pydyf>=0.10,<0.11` trong `requirements/base.txt`.

7. **`CLINIC_INFO`**: shortcode `{{ clinic_name }}` / `{{ clinic_address }}` /
   `{{ clinic_phone }}` đọc từ `settings.CLINIC_INFO` (env `CLINIC_NAME`,
   `CLINIC_ADDRESS`, `CLINIC_PHONE`, ...). Trước đây thông tin phòng khám bị
   hardcode trong `tasks.py`; bộ xuất Excel cũ nay cũng dùng chung nguồn này.

8. **`Report.output_format`** thêm giá trị `html`; `ReportSerializer` đổi field
   `file` (chưa từng được serialize) thành `file_url`.

9. **Bug đã sửa trong quá trình làm**: nhánh PDF cũ ở `tasks.py` ghi
   `file_bytes = b""` rồi vẫn đánh dấu report `done` — tức mọi report PDF trước
   đây đều là file rỗng. Nay PDF không có template sẽ báo lỗi rõ ràng.

10. **Chặn gắn template khoa vào `body_type` không render nó**: chỉ body function
    `department_templates` mới đọc `ReportTemplate.items`. Gắn vào body_type khác
    trước đây vẫn lưu được nhưng phần body âm thầm mất — không cảnh báo gì.
    Nay được chặn ở 4 tầng:
    - `ReportTemplateSerializer.validate()` — chặn cả 2 chiều: thêm items vào
      body_type sai, và đổi body_type khi đã có items (HTTP 400)
    - `ReportTemplateItemInlineFormSet.clean()` — chặn trong Django admin
    - `render_report()` — ghi log WARNING cho dữ liệu tạo bằng shell/fixture
    - Changelist + trang preview trong admin — hiển thị cảnh báo đỏ

11. **Bug nghiêm trọng phát hiện khi viết test cho mục 10**: sandbox template
    trước đây gọi `library.tags.pop()` trên kết quả `import_library()`, mà hàm
    này trả về **singleton `register` cấp module** dùng chung cho mọi Engine
    trong process. Hệ quả: `{% extends %}`, `{% include %}`, `{% load %}` bị xoá
    khỏi **toàn bộ** Django — làm sập trang admin ngay khi module `reports.render`
    được import. Đã thay bằng `RestrictedEngine.get_template_builtins()` +
    `_RestrictedLibrary` (wrapper chỉ-đọc), không sửa state dùng chung.

12. **`_sync_items` bỏ mất `exam_template`**: item tạo qua API mất phần ghim mẫu
    nhập liệu nên render cả các mẫu khác của cùng khoa. Đã sửa + thêm test.

13. **Built-in template tags**: `reports/report_tags.py` đăng ký các function render
    dùng được trực tiếp trong `header_html` / `body_html` / `footer_html` mà
    **không cần `{% load %}`**. `reports.report_tags` được thêm vào `builtins` của
    sandbox engine (`RestrictedEngine` → `get_template_engine()`), nên tag tự động
    có sẵn. Hàm render nằm trong `reports/result_table.py` (tách riêng để tránh
    circular import giữa `render.py` ↔ `report_tags.py`). Để thêm function mới:
    đăng ký thêm `@register.simple_tag(takes_context=True)` trong `report_tags.py`.

    Các tag hiện có:
    - `{% result_table %}` — bảng chi tiết 1 patient (dùng `patient` trong context)
    - `{% company_summary_table %}` — bảng tổng hợp flat nhiều nhân viên (dùng
      `dataset.table` từ `build_clinical_detail_report`, 1 dòng/NV, không merge header)
    - `{% clinical_detail_table %}` — bảng chi tiết ngang (dùng
      `BodyBuilder.clinical_detail_table`, header merge R7/R8/R9/R10)
    - `{% cost_table %}` — bảng chi phí theo nhân viên (dùng `DepartmentField.default_price`,
      nhận biết `pricing_mode` per_field/package_total)
