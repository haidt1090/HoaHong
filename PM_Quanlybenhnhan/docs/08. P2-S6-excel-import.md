---

## Goal

Each department imports its own Excel file independently — a lab technician uploads blood test results, a radiologist uploads X-ray results, etc. The system maps columns to department fields, matches rows to patients by `employee_code` **within a selected company**, creates/finds `Examination` using a chosen `ExamPackage`, and updates only that department's `DepartmentResult`.

Additionally, users can **download a blank Excel template** for each department (pre-built from the `DepartmentTemplate.fields_config`) so they know exactly what columns to fill.

## Tasks

### Excel Export (Async — Pre-populated with Employee Data)

#### Trigger Export
- [ ] `POST /api/export/`
  - Request: `{company_id, package_id, department_id, exam_date?}`
  - Response: `{export_id, status: 'processing'}` — **returns immediately**
  - Triggers an async Celery task to generate the Excel file
  - For small datasets (<50 employees): may complete synchronously, returning `status: 'done'` with `download_url` immediately

#### Poll Status
- [ ] `GET /api/export/{id}/`
  - Response: `{export_id, status: 'processing' | 'done' | 'failed', download_url?, error_message?, progress: {current, total}}`

#### Download
- [ ] `GET /api/export/{id}/download/`
  - Returns the `.xlsx` file with `Content-Disposition: attachment; filename="ACB_Kham_suc_khoe_dinh_ky_Xet_nghiem_mau.xlsx"`

#### Export Flow
1. User clicks **"Xuất Excel"** on import page
2. Frontend sends `POST /api/export/` → gets `export_id` back immediately
3. Backend Celery task:
   - Fetch all employees of the company
   - For each employee, query `Examination` + `DepartmentResult` for the target department+package+exam_date
   - Build Excel with openpyxl: 3 header rows + data rows
   - Save to `MEDIA_ROOT/exports/{export_id}.xlsx`
   - Mark job status = `done` with `download_url`
4. Frontend polls `GET /api/export/{id}/` every 1-2 seconds
5. When `status === 'done'`: show download button, auto-trigger download, or show link
6. Export files auto-deleted after 24 hours (Celery beat or cron)

#### File Content
  - File name format: `{Company Code}_{ExamPackage Name}_{Template Name}_result.xlsx`
    - Example: `TC001_Goi_kham_dinh_ky_Template_XN_mau_result.xlsx`
  - Row 1: column headers = `Mã NV`, `Họ tên`, then `fields_config[*].label` in Vietnamese
  - Row 2: units (from `field.unit`) — empty for `Mã NV` and `Họ tên` columns
  - Row 3+: **all employees** of the company (one per row):
    - Columns A-B: `employee_code`, `full_name` (pre-filled from company employee list, **locked**)
    - Remaining columns: existing exam result values, or blank if not yet examined
  - **No normal range row** — file contains only exam results
  - **Backend auto-maps `label` → `key` during import** (column matching by label, case-insensitive, trimmed whitespace; fuzzy matching as fallback)

#### Frontend UX
- [ ] "Xuất Excel" button → disabled while export is processing → shows spinner + progress text (e.g., "Đang tạo file... 45/200")
- [ ] When done: button changes to "Tải xuống" with download icon, auto-triggers browser download
- [ ] On failure: red error message with retry button

### Per-Department Import (with Company & ExamPackage selection)
- [x] Import endpoint: `POST /api/examinations/import/{department_id}/`
  - **Required request fields:**
    - `company_id` (UUID) — company whose employees are being imported
    - `exam_package_id` (UUID) — active exam package from that company
    - `exam_date` (date, default today) — examination date for all rows
    - `file` (.xlsx) — Excel file with data
  - Import flow per row:
    1. Find Patient by `employee_code` (column A) filtered by `company_id`; `full_name` (column B) is for human reference only — ignored during import
    2. Find or create `CompanyExamPackage` linking company + exam_package
    3. Find existing `Examination` for this patient on `exam_date`:
       - **If found:** ensure all package department results exist (spawn missing ones), update exam to status=confirmed, doctor=current_user
       - **If not found:** create new Examination with:
         - `company_exam_package` = the CompanyExamPackage
         - `exam_package` = the selected ExamPackage
         - `exam_type` = auto-filled from the ExamPackage
         - `status` = `confirmed` (Xác nhận)
         - `doctor` = current logged-in user
         - All DepartmentResults auto-spawned from the package departments
    4. Find or create `DepartmentResult` for the import target department
    5. Update `DepartmentResult.data` with row values: non-empty cells overwrite existing values; empty cells are **skipped** (preserve existing data)
    6. Set `DepartmentResult.completed_by` = current user
  - Validation:
    - `employee_code` not found → skip row + report error
    - Column header not recognized (no matching field label) → skip column value
    - Duplicate employee_code → update existing DepartmentResult, not duplicate
  - **Column mapping**: header row (row 1) contains Vietnamese labels → backend resolves each label to its `fields_config[*].key` via case-insensitive matching
  - **Empty cell behavior**: empty cells do NOT clear existing data — they are skipped. To clear a value, the cell must contain a special sentinel (e.g., `#CLEAR#`)
  - Async via Celery for files > 100 rows
- [x] Import result: `GET /api/import/{id}/`
  - Returns: `id`, `department`, `exam_date`, `status`, `total_rows`, `success_count`, `updated_count`, `skipped_count`, `errors[]`

### Frontend import page flow:
  - Step 1: Select Company → shows active ExamPackages for that company (via `/api/companies/{id}/packages/`)
  - Step 2: Select ExamPackage → exam_type auto-filled
  - Step 3: Select Department (target for the Excel data)
  - Step 4: Select exam date
  - Step 5: Upload Excel file (drag-drop or file input)
  - Step 6: Preview column mapping (system auto-detects; user can adjust)
  - Step 7: Import → progress bar → result summary
  - "Tải mẫu Excel" button visible at Department step

## Technical Notes

- Template generation uses `openpyxl` with data validation and formatting.
- **Async export**: For companies with many employees, generating the Excel is a Celery task. Small datasets (<50 employees) may complete synchronously (return `status: 'done'` in the POST response immediately). Export files stored at `MEDIA_ROOT/exports/{export_id}.xlsx`, deleted after 24h by Celery Beat or file cleanup task.
- **Column mapping during import**: headers in Excel are Vietnamese labels (`field.label`), NOT field keys. Backend must maintain a `label → key` mapping from the template's `fields_config` to resolve column values. Matching is case-insensitive and trims whitespace; fuzzy matching for Vietnamese labels as secondary fallback.
- `CompanyExamPackage.get_or_create` ensures the link exists; `pricing_mode` defaults to `package_total` for import-created links.
- `Examination` is set to `confirmed` immediately on import, bypassing the draft→completed→confirmed workflow (import implies the data is already final).
- **Export filename**: `{Company.code}_{ExamPackage.name}_{DepartmentTemplate.name}.xlsx` — spaces/special chars replaced with underscores. Vietnamese characters preserved.
