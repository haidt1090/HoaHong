# Phase 1 — Sprint 1: Project Scaffold

- **Phase:** 1 — Foundation
- **Sprint:** 1
- **Priority:** 🔴 Critical
- **Django App(s):** `config/`, `core/`
- **Depends on:** none

---

## Goal

Set up the project skeleton, containerized dev environment, tooling, and a working health check endpoint. At the end of this sprint, any developer can clone the repo and run `docker-compose up` to get a running Django + PostgreSQL(pgvector) + Redis stack.

---

## Tasks

- [ ] Initialize Django project with split settings `config/settings/`
  - `base.py` (shared), `dev.py`, `prod.py`
- [ ] Docker Compose services:
  - `web` (Django + Gunicorn)
  - `db` (PostgreSQL 16 with pgvector image, e.g. `pgvector/pgvector:pg16`)
  - `redis` (Celery broker + cache)
  - `worker` (Celery worker)
  - `nginx` (reverse proxy, prod-like)
- [ ] `django-environ` for environment variables loaded from `.env`
- [ ] Python dependency management (poetry **or** pip-tools) with pinned versions
- [ ] Git init + `.gitignore` (Python, Django, Node, `.env`, media)
- [ ] Pre-commit hooks: `ruff`, `black`, `isort`, end-of-file-fixer
- [ ] `README.md` with setup instructions
- [ ] Health check endpoint: `GET /api/health/` returns `{ "status": "ok", "db": "ok", "redis": "ok" }`
- [ ] CORS configuration (`django-cors-headers`) for the PWA origin
- [ ] Logging configuration (console + rotating file handler)
- [ ] Standardized API error handling middleware / DRF exception handler
- [ ] `core/` app scaffolded with `BaseModel`, `VersionedModel` abstract models

## Acceptance Criteria

- `docker-compose up -d` starts all services with no errors
- `docker-compose run web python manage.py migrate` completes
- `curl http://localhost:8000/api/health/` returns `200` and reports DB + Redis reachable
- pgvector extension can be created (`CREATE EXTENSION vector;` succeeds in the db container)
- Pre-commit hooks run on `git commit` and block on lint errors

---

## Technical Notes

- Use the `pgvector/pgvector:pg16` Docker image so the extension is preinstalled.
- Keep secrets out of the repo — `.env` is gitignored, `.env.example` is committed.
- The DRF custom exception handler should return a consistent error shape:
  ```json
  { "error": { "code": "validation_error", "detail": "...", "fields": {} } }
  ```
