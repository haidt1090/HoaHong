## Goal

Add keyboard shortcuts to data entry screens to accelerate bulk data entry. The goal is to let users keep their hands on the keyboard, minimizing mouse interaction.

---

## Context / Problem

Health-check data entry for hundreds of employees is repetitive:
1. Select an employee
2. Enter results per department
3. Save (click "Lưu" button)
4. Move to the next employee (mouse click)

Each mouse click costs 1-2 seconds. With 500 employees × 5 departments, mouse work consumes hours. Keyboard shortcuts keep the operator's hands on the keyboard.

## Usage Guide

### Data Entry — typical workflow

A typical batch-entry session (enter results for one company):

1. **Open the "Nhập liệu" tab** on the company detail page.
2. **Select an employee** (Panel A — search & click, or `Ctrl+F` in the employee list).
3. **Enter results** for each department. Press `Ctrl+1..9` to jump between department tabs.
4. **Save the current department** with `Ctrl+S`.
5. **Save all + move to next employee** with `Ctrl+Q` — this saves all unsaved departments and auto-selects the next employee.
6. Repeat steps 3-5 until all employees are done.

### Modifier combos vs plain keys

- **Modifier combos** (`Ctrl+S`, `Ctrl+Q`, `Ctrl+1..9`) fire **anywhere** — even while focus is inside an input cell. They are safe because `Ctrl` is never typed into a field.
- **Plain keys** (`↑`, `↓`, `Enter`, `Delete`) only fire when focus is **not** inside a text input. This prevents accidental actions while typing.

### Viewing all shortcuts

- Press the **`?`** button (or the keyboard icon) in the top bar of the data entry screen to open the **"Phím tắt"** modal, which lists every active shortcut for the current screen.

### Avoiding browser conflicts

- `Ctrl+S` is intercepted and the browser's native "Save page" dialog is suppressed.
- `Ctrl+Q` is intercepted (some browsers use it to quit). `e.preventDefault()` is called.
- `Ctrl+1..9` may conflict with browser tab switching (`Ctrl+1`..`Ctrl+8` switch tabs). Verify the browser profile; if conflict arises, these are configurable in `src/shortcuts.ts`.

### Configuration

All shortcuts are defined centrally in `src/shortcuts.ts`:

```ts
export const SHORTCUTS = {
  saveDept: { combo: 'ctrl+s', handler: 'saveCurrentDepartment' },
  saveAll: { combo: 'ctrl+shift+s', handler: 'saveAllDepartments' },
  saveAndNext: { combo: 'ctrl+q', handler: 'saveAndNextEmployee' },
  // ...
}
```

To disable a shortcut, remove it from the map or set `enabled: false`.

## Technical Notes

- **Composable pattern**: `useKeyboardShortcuts` uses `onMounted`/`onUnmounted` to attach/detach listeners, avoiding memory leaks.
- **Focus guard**: do not trigger shortcuts while typing in a text field (except modifier combos).
- **Reusability**: shared composable across all screens — no copy-paste handlers.
- **Prevent default**: `Ctrl+S` must call `e.preventDefault()` to block the browser save dialog.
- **Accessibility**: shortcuts do not fully replace mouse interaction — all buttons remain clickable.
