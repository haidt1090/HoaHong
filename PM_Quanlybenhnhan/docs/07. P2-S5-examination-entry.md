## Goal

Replace the old 5-JSONField Examination model with a dynamic, department-driven design. Each examination spawns multiple `DepartmentResult` rows (one per department in the chosen package). Permissions lock at the department level (Nurse fills Lâm sàng, LabTech fills Xét nghiệm/X-Quang/Siêu âm).

## Status Workflow

```
draft ──(auto: all dept fields filled)──▶ completed ──(manual: doctor/admin)──▶ confirmed
                                              ▲                                  │
                                              └──────(admin reopen)─────────────┘
```

- **`draft`**: Not all department fields are filled (auto-computed, read-only).
- **`completed`**: ALL fields across ALL departments have data (auto-computed when last field is filled).
- **`confirmed`**: Doctor or Admin manually locks the exam (immutable except Admin can reopen to `completed`).

The `status` API endpoint (`PATCH /api/examinations/{id}/status/`) only supports:
- `completed → confirmed` (doctor/admin)
- `confirmed → completed` (admin reopen)

Setting `draft` or `completed` manually returns 400.
Status is automatically recomputed on every `DepartmentResult.save()` via `Examination.recompute_status()`.

## Permission Notes (Department-Level — Runtime Lookup)

Permission checks use **runtime** `Department.category`, not a snapshot. This means changing a department's category later affects new edits on existing exams (but not previously saved data).

| Role | Can Edit Departments (by `Department.category`) |
|------|--------------------------------------------------|
| **Doctor** | All departments + conclusion |
| **Nurse** | `category='clinical'` (Lâm sàng, Mắt, Da liễu, TMH, ...) |
| **LabTech** | `category='para_clinical'` (Xét nghiệm, X-Quang, Siêu âm, ...) |
| **Admin** | All departments |

```python
# core/permissions.py (runtime lookup — no snapshot needed)
ROLE_DEPT_CATEGORY = {
    'nurse': 'clinical',
    'labtech': 'para_clinical',
}

def can_edit_department(user_role, department):
    if user_role in ('admin', 'doctor'):
        return True
    allowed = ROLE_DEPT_CATEGORY.get(user_role)
    return allowed == department.category  # runtime lookup
```

- A Nurse can see all department tabs but only edit those with `category='clinical'`
- A LabTech can see all department tabs but only edit those with `category='para_clinical'`
- UI greys out non-assigned department tabs

## Technical Notes

- On examination creation, iterate the package's `ExamPackageDepartment` rows, create one `DepartmentResult` per department, copying `template.fields_config` into `template_snapshot`.
- This snapshot ensures the exam form doesn't change if the template is updated later.
- Permission checks use **runtime** `Department.category` lookup — no snapshot needed for RBAC. See `core.permissions.can_edit_department()`.
- Status `draft` / `completed` is auto-computed by `Examination.recompute_status()`, called from `DepartmentResult.save()`. The computation checks: ALL `DepartmentResult` rows exist, and every field key in `template_snapshot` has a non-empty value in `data`.
- `confirmed` remains manual — it locks the exam against further edits (except by Admin reopening via `confirmed → completed`).
- The frontend form is now a tab-per-department layout (see Sprint 10 P2-SF1).

### Admin Add Form — `exam_type` Auto-fill

- `ExaminationAdmin` uses a custom `change_form_template` (`admin/examinations/examination/change_form.html`).
- `exam_type` is rendered as a dropdown by Django admin (no custom form needed) thanks to `choices=ExamPackage.EXAM_TYPES` on the model field.
- A custom URL `/admin/examinations/examination/package-exam-type/?package_id=X` returns the `exam_type` for a given `ExamPackage`.
- JavaScript in the template listens for `change` and `select2:select` events on the `exam_package` autocomplete widget. When a package is selected, it fetches the exam type and auto-fills the `exam_type` dropdown.
- The `select2:clear` event resets `exam_type` to empty.
- Source files: `examinations/admin.py` (`_package_exam_type_view`), `templates/admin/examinations/examination/change_form.html`.
